================================================================================
SECTION 2 — WHY WE MIGRATED FROM FIREBASE
================================================================================
Firebase Spark plan does NOT allow Cloud Functions.
Password reset requires server-side Admin SDK.
Blaze plan requires credit card — not viable for a Pakistani student.

Alternatives evaluated:
  - Appwrite: laggy, migration tool crashed on nested structures. Rejected.
  - PocketBase: laptop 24/7 issue. Rejected.
  - Supabase: ✅ CHOSEN.

Supabase Free Tier:
  500 MB database, 1 GB storage, 50,000 MAU,
  500,000 edge function invocations, unlimited API requests, no CC.

SECTION 6 — TABLE SCHEMAS (Supabase = snake_case)
================================================================================
departments         : id(text PK), name, is_active, created_at
teachers: id(text PK), login_code(text unique), full_name,
          contact_email, auth_email, role, is_active, created_at
admins              : id(text PK), full_name, email, role, is_active,
                      created_at
sections            : id(text PK), department_id→departments,
                      year(int 1-4), name, academic_year,
                      total_students(int), is_active, created_at
students            : id(uuid PK auto), full_name, roll_no, enrollment_id,
                      department_id→departments, section_id→sections,
                      year(int), is_active, created_at,
                      unique(section_id, roll_no)
subjects            : id(text PK), name, credit_hours(int),
                      department_id→departments, year(int), semester(int),
                      is_active, created_at
teaching_assignments: id(uuid PK auto), teacher_id→teachers,
                      teacher_name, subject_id→subjects, subject_name,
                      section_id→sections, academic_year, semester(int),
                      created_at

RLS: every table has auth_read + auth_write policies for role=authenticated.

SECTION 8 — GIT WORKFLOW (PROFESSIONAL)
================================================================================
Never commit to main. Feature branches + PRs.

  git checkout main
  git pull origin main
  git checkout -b feature/xyz
  flutter analyze && flutter test
  git add . && git commit -m "feat: xyz"
  git push -u origin feature/xyz
  → GitHub: Compare & PR → wait CI ✅ → Merge → Delete branch
  git checkout main && git pull && git branch -D feature/xyz

Recovery:
  git restore <file>           discard file changes
  git checkout -f main         force switch
  git branch -D <branch>       force delete
  git remote remove origin / add origin <URL>

Commit types: feat, fix, chore, docs, refactor, style, test
